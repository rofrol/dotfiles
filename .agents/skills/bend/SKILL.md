## Code

- A def may call only defs written above it: put helpers (`foo.pick`,
  `foo.go`) before their callers. Mutual recursion is refused; a loop that
  needs a computed value passes it as a parameter. A def used before it is
  written is reported as "an unfilled law". (2.0.35)
- `match` takes parameters or pattern-bound variables only, never a computed
  value, and scrutinees follow parameter order: to branch on a computed
  Bool, call a helper whose parameter it is. A destructuring let
  (`(a, b) = p`) or a rewrite may not come before a `match` on a parameter;
  put it inside the case. (2.0.35)
- Variables are affine: a value used twice needs `+name` (its type must be
  `Data`); this holds for equality proofs too (`+e: {a == b : T}`), and for
  pattern variables: `case Some{+n}:`, `case Con{+id, +rest}:`. An erased
  parameter (`-x`) may be used freely in types. (2.0.35)
- A `let` whose value is a constructor literal (`+r = Foo{...}`) or
  `1n+expr` cannot be inferred: build the literal in a def with a return
  type, and write `Nat.add(1n, expr)`. (2.0.35)
- Termination reads arguments left to right: the shrinking one goes first
  (`replay(records, tasks)`). A chain followed through a list needs a fuel
  argument (the list's length) to terminate. (2.0.35)
- `&&` and `||` associate to the left: `a && b && c` is
  `Bool.and(Bool.and(a, b), c)`. (2.0.35)
- Names taken in Base: `Event`, `Done`/`Fail` (Result), `Maybe.is_some`.
  (2.0.35)

## Running

- `bend file.bend -- args`: without `--`, options such as `--reset` go to
  `bend` itself. The program runs inside the `bend` (bun) process. (2.0.35)
- On that JavaScript lane `Process.run` blocks every computation until its
  child exits, so `IO.fork` cannot overlap two children; a native binary
  (`bend file.bend -o bin`, through clang) runs each child on a helper
  thread. A program whose children must overlap runs natively. (2.0.35)
- A pure generator that runs on the JavaScript lane can be checked against
  its native build: same input, compare the outputs. This catches
  interpreter/native divergence within one compiler version; it is no use
  for programs whose effects differ by lane.

## Proofs

- `%e : P` with `e : {a == b : T}`: `P` is the current goal with `_` where
  `b` occurs; the goal becomes `P` with `a` there. To turn `X` into `Y` in
  the goal, rewrite with `{Y == X}` (often `Equal.sym(T, X, Y, e)`) and mark
  `X`. `Equal.sym(T, a, b, e : {a == b})` gives `{b == a}`. (2.0.35)
- A rewrite acts on the whole goal; when the goal is a pair, build each
  component with `Equal.cong` and `Equal.trans` instead. (2.0.35)
- A goal stuck on a function applied to a non-constructor: rewrite the
  argument into constructor form with an eta lemma (`x == Foo{Foo.a(x), ...}`)
  so pattern-matching defs reduce. (2.0.35)
- Contradictions: `absurd(T, e : {True == False})`; Maybe and Nat clashes
  need discrimination lemmas of your own. (2.0.35)
- A law used by live code must be proven: an unfilled law is "a dead
  claim". A lemma used by a proof must be defined before it. (2.0.35)
- Recursion into a helper: the helper takes the induction hypothesis as a
  closure argument (`ih: {...} -> {...}`), since a helper above cannot call
  the def below it. (2.0.35)
- A recursive proof whose induction hypothesis must be used for several
  values, or a function argument used twice, cannot take that function as a
  parameter (functions are not Data): state the hypothesis as a Bool with an
  equality proof and derive the pointwise fact. (2.0.35)
- A def that matches `fuel list` (`case f Nil{}`) does not reduce while the
  fuel is a variable: prove a small lemma by `match f` and rewrite with it.
  (2.0.35)
- `(a, b) = e` destructures only a parameter or pattern variable; for a
  computed pair use `and_l(...)` and `and_r(...)` with `+` on the proof.
  (2.0.35)
- A lambda parameter used twice is written `+x => ...`; a pattern variable of
  a successor is `1n+(+g)`. (2.0.35)
- Termination needs the shrinking argument to come before any argument that
  changes; an equation `h == 1n+k` passed in does not count. (2.0.35)
- After a change, run a mutation of the code under proof and check that some
  proof breaks; a law that survives the mutation is too weak.
